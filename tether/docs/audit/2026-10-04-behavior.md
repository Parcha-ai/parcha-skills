# Observable colleague behavior and evaluation — 2026-10-04

Tether has useful foundations: exact native continuation, durable inbound turns, scoped author controls, verified final delivery, and a shared collaboration contract. Its next product milestone should be **finishing useful work through a realistic Slack exchange**, with evidence that the colleague handles corrections, dependencies, and silence sensibly. Successful transport alone does not establish that outcome.

Scope: private candidate source at `60ef226` in this audit worktree; read-only inspection of the installed isolated Hermes runtime and historical receipts. Public GitHub main is separately pinned to `b7b9d0ff8542b289a8389a8d01d9f5ba65705af0` in the comparison below. The preceding candidate-specific implementation findings must not be read as shipped public-main features. Only this document was written. Small pure-function probes ran with `TETHER_HERDR=off`, and process/network entry points were replaced with functions that raise. No native session, Slack request, model request, service change, or broad test suite ran. Historical observations below retain their original scope; they are not current fleet certification.

## Behavioral deficiencies

### 1. Promises, useful outcomes, and receipts are different things

The contract correctly says “A reply or promise does not complete unfinished work” (`team.md:23–27`). The persistent Tether model tracks bindings, turns, attempts, saved answers, and delivery receipts (`store.py:36–131`). It does not connect an attempt's response to a goal's acceptance criterion or to a dependency's eventual fulfillment. A successful final delivery can therefore carry a promise while the useful work remains unfinished.

This should be addressed through existing Hermes task ownership/dependency/artifact state, not another parallel project manager. Require an observable relationship between a substantive commitment, its existing task, the resulting artifact, and the final completion claim. A task that is waiting needs a real supported wake or a named next action. Evaluate that relationship rather than rewarding polished task narration.

### 2. The peer policy confuses message presentation with conversational purpose

`admission.py:54–69,145–150` treats recognized prefixes/phrases as status. A bounded pure-function probe showed that a trusted peer's `:warning: Found a critical regression; review required before merging.` returns `not_ours/peer_status_notice`, whereas `Thanks, looks good.` and a substantive correction both return `admit/trusted_peer_on_bound_thread`. The hook then skips recognized status for every thread (`__init__.py:425–429`). This is an observed policy counterexample, not a claim that an actual review message was lost today.

`active.py:615–621` caps consecutive messages from the same peer. That prevents one simple loop but can suppress a necessary later review round. Changing peers resets the count; a multi-agent loop can continue. The existing test intentionally proves different peers stay admitted (`tests/test_plugin_next_active.py:742–761`). Actor count is not evidence that an exchange adds value.

Keep workspace/identity/session/control checks deterministic. Distinguish authenticated transport housekeeping from substantive text without discarding a review just because it begins with a warning. Evaluate acknowledgment, new evidence, unresolved objection, changed artifact, and genuine request separately. Any semantic policy should initially explain or rank work in shadow; a false “acknowledgment” prediction must not silently discard a correction.

The Oct2 Jev shadow run supplies a concrete warning: `jev-1.13.0` made valid typed responses through the existing local broker, but labeled five of eight new work-needed messages acknowledgment-only. Nonrepeat coverage was seventeen correlated messages from two threads, with no fresh acknowledgment/uncertain coverage. One missed work request had acknowledgment probability 0.91. This is neither calibration evidence nor a safe suppression rule. Preserve it as a held-out failure set; acquire fresh exchanges and fix labels before inference rather than repeatedly optimizing against those outputs.

### 3. “Check the latest decision” depends on the model finding it

`compose_prompt`, `active.py:383–409`, supplies session/destination, currently bundled admitted messages, and the collaboration contract. `attempt_context`, `store.py:588–609`, supplies that attempt's turns, not a guaranteed latest Slack decision or current artifact version. Native resumption preserves the session's own history, but another colleague's thread contribution or updated artifact may not be there. Optional external preparation is capped at 8,000 characters and fails open while preserving the request (`active.py:1075–1081`); the profile-scoped hook seam is sound (`__init__.py:665–717`) but provides no mandatory decision snapshot.

The prompt asks the agent to check current decisions, retrieve memory, and review changed work (`team.md:36–47`). Those instructions need an inspectable context package: latest human decision, unresolved questions/objections, current artifact/version, dependency outcome, and links to source messages. Retain verbatim current requests and provenance. Do not substitute a lossy summary for the evidence.

Also, native `colleague_contract()` partitions the file at `## Work together` (`active.py:374–380`). It excludes the earlier roster and “a direct human request is never NO_REPLY” rule (`team.md:18–19`). The attached native session may have other instructions, but this wrapper does not supply that rule. `SessionDriver.run_turn` accepts a final silence marker regardless of who asked (`session_driver.py:902–904`). Direct-human response recall therefore needs an explicit behavioral test; marker-parser tests cannot guarantee it.

### 4. Progress and stop behavior are truthful but incomplete

Presence uses seen/done/failure/blocked reactions (`active.py:279–283,645–647,1174–1181`), while generic gateway notices are suppressed (`__init__.py:321–332`). That reduces noise. A long task still has little structured user-visible evidence of whether it is working, waiting on a dependency, or unable to act. “Seen” alone does not resolve that uncertainty. The native transport offers an `on_event` callback, but `_session_for` does not pass it (`session_driver.py:1079–1085`); event liveness is currently stronger than product-level progress visibility.

Add sparse, meaningful updates tied to an actual state change or user status request: what completed, what remains, and the real dependency/blocker. Do not restore elapsed-time chatter or expose tool traces. Measure stalled silence separately from deliberate silence.

Exact owned-turn cancellation currently supports Codex app-server; Claude/Herdr return unsupported (`session_driver.py:808–827`). The stop message correctly explains that interruption is unconfirmed and retains the fence. For the default Claude experience, this is a significant product limitation: an operator cannot assume `/stop` stopped its computation. Improve the first-party cancellation contract and test the requested/confirmed/completed race before simplifying the wording.

Saved-result recovery is another distinct UX state. The actual installed Alpha baseline fixture on Oct3 showed one counted fake native final remained saved but terminal `delivery_prepare_failed` through three fresh recovery processes, without sending or rerunning. It establishes the old preparation gap, not the correctness of the later evolving recovery candidate. The new source has recovery paths and better messages; the unexecuted preliminary matrix is not proof those paths work. A user should be able to ask for the status of an existing result without triggering its computation again.

## The current evaluation cannot answer the product question

`evals/conversation/conversation_eval.py` is a useful starting corpus/measurement tool, but has important limits:

* Export drops roots with no replies (`:88–89`), removing precisely the unanswered-work episodes we need to measure. Thread replies are capped at 100 without pagination (`:90`).
* `measure`, `:107–135`, counts any addressee reply as answered. The audit probe gave **identical metrics** to “I will do it later” and “Implemented. Actual tests and artifact attached.” It measures first reply latency, not verified outcome latency or follow-through. Unmentioned direct-human requests also lack the addressee denominator.
* The shipped September fixture contains ten threads: eight addressee replies, median first reply 21s, one marker leak, one bare mention, three status lines, five threads with extra voices. These are historical fixture results, not current live behavior. Q2 is absent from `AGENTS` (`:28–32`).
* The semantic rubric penalizes answering someone else's question and rewards a routing decline (`:39–48`), while the current team contract invites useful contributions beyond specialty (`team.md:29–33`). A beneficial unsolicited review and an unanswered handoff can be scored against the product's actual goal.
* Judges truncate each message to 600 characters (`:156`) and see no artifact/tool/receipt chain. They cannot establish that a claimed fix happened. JSON is regex-extracted and integer-converted without explicit 0–2/schema validation (`:138–148,164–171`); missing votes must remain missing evidence. Three votes from one model are not independent human validation.
* The exporter requires a raw Slack bot token and calls Slack directly (`:52–56,190–195`); the judge launches a bare Claude CLI with a stale default model (`:138–142,187`). Do not run those operational paths as the new evaluation workflow. Use supported Tether readback and explicit existing-broker routing/model provenance.

## A behavioral roadmap

### First: establish an outcome-based episode benchmark

Create versioned, privacy-reviewed episodes with a concrete request, artifact acceptance oracle, authorized actors, native owner, interruption schedule, and expected disposition. Cover direct-human work; clarification; attachment access; burst correction; reviewer objection; addressed-to-another-agent useful contribution; acknowledgment; duplicate event; actual dependency wait/wake; stop; and saved-final delivery failure. Include unanswered roots and unfinished commitments. Scripted offline fixtures validate routing/state; separately authorized real broker runs validate behavior. Never call a fake fixture proof of intelligent work.

Report results per episode and failure cohort, with raw provenance and execution costs. Separate transport invariants from behavioral quality. Blind labels must be fixed before model inference; hold out whole tasks/threads, not nearby correlated messages. Compare current policy, revised prompts/context, and any Jev shadow on the same held-out episodes. Include disagreement and abstention instead of hiding missing judgments.

| Measure | Unit and oracle |
| --- | --- |
| Useful outcome completion | Fraction of eligible requests with an independently verified artifact satisfying the request; promises/routing alone do not count. |
| Commitment follow-through | Fraction of substantive commitments fulfilled or truthfully resolved by the deadline, including arranged dependency wakes; measure unsupported promises separately. |
| Correction and review incorporation | Fraction of actionable objections resolved in the actual changed artifact; record lost corrections, needless complete re-review, and review rounds. |
| Appropriate speech and silence | Human-request response recall; peer work-needed recall; unnecessary reply rate; beneficial unsolicited contribution precision; uncertain abstentions. Score meaning, not marker syntax or actor count. |
| Context fidelity | Wrong-goal/wrong-artifact decisions and stale-answer rate after a human change; verify decision/artifact versions and attachment accessibility. |
| User-visible trust | Accurate working/waiting/blocked/delivered/stopped state, false completion/stop claims, duplicate visible results, and time to verified outcome (p50/p90 plus unresolved censored episodes). |
| Efficiency | Model/tool cost and elapsed time per accepted outcome; operator interventions per task; unnecessary turns per resolved exchange. |

Safety invariants remain exact: unauthorized control, wrong-session execution, wrong-target reply, and native rerun of a known saved final must be zero in the corresponding deterministic cases. Behavioral improvement thresholds should be set against measured baseline, not invented fleet-wide percentages. Estimate uncertainty by independent episode/task; correlated message counts are not sample sizes.

### Next: make commitments and context inspectable

Use existing Hermes tasks for owned work and dependencies. Attach the current goal, task/artifact references, unresolved objection, and supported wake to the ongoing session. Supply a small provenance-bearing latest-decision package at continuation and on review. Expose a concise status answer from actual task/native/delivery state. Preserve session identity, permission boundaries, human changes, and the original request. Run the benchmark after each narrow change; check completion and stale decisions, not just shorter replies.

### Then: improve collaboration with measured judgment

Replace text-prefix housekeeping suppression with explicit trusted event classification. Keep simple deterministic loop budgets as resource controls, but report when they stop an unresolved exchange instead of treating the cap as completion. Trial semantic interpretation in shadow on fresh balanced cohorts, including mixed signoff-plus-action and split reviews. Jev can provide typed judgments through the existing broker; its predictions should not become author admission, human approval, or session control. Promote only an observed improvement in useful review/coordination with no concealed work-needed losses. This yields a colleague that advances work, contributes ideas, and knows when quiet is useful.

The strongest evaluation/routing counterexamples **apply to both sources**. The conversation evaluator and its tests are byte-identical between these commits. A bounded second pure-function probe executed public-main admission/evaluator code in memory, with live process/network calls forbidden, and reproduced: substantive warning-prefixed review rejected as `peer_status_notice`; acknowledgment admitted; promises and claimed artifacts receiving identical structural metrics; Q2 absent from the roster. Public admission has the same prefix filter (`admission.py:53–68,120–125`) and same trusted-peer admit branch (`:149–155`). Its native same-peer cap (`active.py:628–634`) has the same count-based limitations.

Some findings require different wording across sources. Public native `compose_prompt`, `active.py:397–443`, does **not** call the private `colleague_contract()` partition helper; instead it embeds a fixed wrapper telling the session to act, report evidence, mention the addressee, and keep at most three sentences. The specific omitted-human-rule-through-partition finding belongs only to the private helper. Public's fixed wrapper also lacks an explicit direct-human-never-silent rule and mandatory latest-decision snapshot, but that is a separately inspected omission. The public v6 system-prompt policy states the human rule; attached native sessions may have their own instructions. Neither source's transport syntax alone establishes appropriate human-request response recall.

Consequently, start the proposed episode benchmark on **both pinned implementations**, recording the executing source/runtime/policy and supported features for each run. Report public-main limitations separately from improvements already present privately. Then choose a coherent supported OSS contract and port only the behavior needed to satisfy it, with task-outcome evidence. Do not present a private-host success receipt as proof of the published package, or conflate implementation convergence with product quality.
