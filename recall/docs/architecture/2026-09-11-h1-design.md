## Root cause summary (what the code actually does)

1. **Logical commit is replace-not-update.** `logical_evidence_projection.py:1192-1241` DELETEs and re-INSERTs `canonical_evidence_documents` with `revision+1`. The FK from `canonical_passage_documents` (`schema/041:22-27`, `ON DELETE CASCADE`, keyed on `revision`) cascades to passages, actors, embeddings on *every* session change. The S3 side is already append-friendly: unchanged parts are reused by `(ordinal, content_sha256)` (`logical_evidence.py:779-792`), so only the DB rows churn.
2. **Passage ids are revision- and ordinal-bound.** `passage_projection.py:384-409` hashes `revision` and `len(passages)` into `passage_id`, so even byte-identical prefix windows get new ids; `passage_index.py:413-422` then does DELETE-cascade + COPY.
3. **No quiet period.** `mark_logical_evidence_dirty` (`logical_evidence_projection.py:50-84`) bumps `generation` per ingest request; `_pending` (`:397-437`) selects by `changed_at` ascending with no minimum age. The passage queue only has a "prefer >5 min old" ordering (`passage_index.py:172-175`), not a gate.
4. **Parquet rebuilds a whole source-month** on any ldoc change (`passage_index.py:549-574`, `parquet_scan.py:985-1167`).

### T3. Stable passage identity + differential passage commit (G1) — 2–3 days

**Files:** `passage_projection.py` (`build_passages:319-449`), `passage_index.py` (`_prepare:276-349`, `_commit:351-575`, `project_pending:577`), `projection_worker.py` (metrics), `tests/test_passage_projection.py`.

**Turn unit:** a *record-window* keyed by record ordinals and byte spans. Because `build_passages` windows tokens from ordinal 0 with fixed target/overlap, appending records only alters the final (short) window; every earlier window is byte-identical. So identity = `sha256(tenant, source, ldoc, policy.fingerprint, text_sha256, spans[(record_ordinal, record_count, source_byte_start, source_byte_end)])` — drop `revision` and `len(passages)` from `passage_projection.py:384-400`. A window is thus a stable "turn" for any change strictly after it; a mid-document change (single-record forget) intentionally reflows everything after that point, which is the correct tombstone semantic.

**Commit diff** (`passage_index.py:_commit`):
1. Keep the queue/stale checks (`:359-392`).
2. `SELECT passage_id, text_sha256 FROM canonical_passages WHERE (tenant, source, ldoc)` → `existing`.
3. `to_delete = existing − new_ids`; `to_insert = new − existing`; `retained = ∩`.
4. Keep the `recall_reusable_passage_embeddings` temp table but scope it to `to_delete` (embedding reuse for shifted-but-identical text).
5. `DELETE FROM canonical_passages WHERE passage_id = ANY(to_delete)` (cascades actors/embeddings for those only), then `UPDATE canonical_passage_documents SET revision, source_document_sha256, dense_message_*, passage_count` in place (INSERT ON CONFLICT DO UPDATE), COPY `to_insert` passages + actors, re-attach embeddings for `to_insert` from the temp table. Retained rows are not touched (no UPDATE → no GIN/HNSW churn). Ordinal uniqueness: retained ordinals are a strict prefix, deleted ordinals are freed before insert, so the new UNIQUE holds.
6. Return `{"inserted", "deleted", "retained"}`; `project_pending` sums them; worker logs `passages_inserted/passages_deleted/passages_retained` (rename `passages` to `passages_inserted` in the log line, keep `passages` key for `test_projection_worker.py`).

Receipts are chunk receipts (`canonical_chunks.receipt`, stable) and are unaffected; passage `receipts[]` is derived from spans, so retained rows already have the right values.

**Back-compat:** existing rows have old-formula ids; on first re-projection after deploy they are all `to_delete` (one-time full rewrite per session, same as today). Do this once with debounce on. Embeddings reuse by `text_sha256` covers the vast majority.
